# Decisions and options

This layout replaces `pxrd-evolution-v12-20261020` (left in place, unchanged since its last validation). The first tungstate run under it, with literal library truths, was stopped on 2026-10-22; that folder is archived as `pxrd-evolution-20261022` (decision 19). The second, with reference mismatch, ran for about five hours (P0 and packages v1–v3 on one batch) and was stopped on 2026-10-23; that folder is archived as `pxrd-evolution-20261023`. The third, with analogue withholding and scorer 7.0.0, ran P0 and packages v1–v2 on one batch and was stopped on 2026-10-23; it is archived as `pxrd-evolution-20261023b`. A parallel run (`pxrd-evolution-parallel`, run `tungstates-parallel`) tested the user's reworked PROMPT.md with up to four revisions per cycle; it ran P0 and packages v1–v3 over two batches and was paused on 2026-10-23 at 21:40. This folder was rebuilt from that run's framework and labs. The process is V11's: researcher prompt, P0, scorer semantics, development cycle, transfer batches, continuations, investigations and monitor. The generator physics is V12's. What follows is what changed to make PROMPT.md, TOOLS.md and the code shared across labs, with LAB.md the only lab-specific document.

## Decisions made

### Layout
1. **Framework, labs and runs.** `framework/` is shared and never run in place. `labs/NAME/LAB.md` describes one lab. `new_run.py` builds `runs/NAME/` as a frozen copy of the framework plus that LAB.md, and records a digest of the framework in `RUN.json`. Both demonstrations therefore run identical code and instructions, and a run cannot drift if the framework is edited later.
2. **One settings block in LAB.md.** Generator settings live in a fenced `json lab-settings` block inside LAB.md, so there is one lab file. The researcher reads the whole file, distributions included, as V11's researcher read protocol.json.
3. **Generic text moved out of LAB.md, wording kept.**
   - The three case-selection sentences now open PROMPT.md step 1.
   - The resource and experimental-rule bullets are TOOLS.md's new "Rules" section.
   - LAB.md keeps only the application, the measurement and solver inputs, and the settings block.
4. **Names.** `scoring_v5` → `scorer`. Settings, tmux and service names, and the researcher's permission profile all derive from the run name (`pxrd-divalent-tungstates`). No folder or profile carries a version number.

### Generator
5. **All lab properties come from LAB.md.** Covered: geometry, goniometer radius, radiation, scan grid, count levels, zero-offset and instrument-profile distributions, background, every specimen effect, and the solver-input format. The framework keeps only lab-independent audit settings in `runtime/generator_defaults.json`:
   - oracle fraction tolerance 0.03 and detectability threshold 0.25 noise units;
   - structure-matcher tolerances;
   - registration Uiso 0.005 Å², at most 16 phases, perturbation limits;
   - the instrument-draw seed.
6. **Generic solver inputs.** LAB.md declares the solver-visible sample fields: types `formula`, `formula_list`, `number` and `string`, with optional counts, ranges, choices and nullability. It also gives the `pattern.csv` columns and line ending, and a template that reproduces the lab's experimental `metadata.json`.
   - Recipes carry `sample: {...}`.
   - Synthetic solvers receive exactly the experimental file set: `pattern.csv` and `metadata.json`, with no instrument file.
   - P0.md names those two files, so every lab must use them.
7. **Element consistency.** Phases may contain only elements supplied by LAB.md's element-source fields, plus its ambient elements. Each lab can also require every supplied element to appear in some phase. The resulting allowed-element list is stored in the case's private record, and the scorer reads it there.
8. **Single-wavelength radiation.** Set `wavelength_ka2_A: null` for Kα1-only or synchrotron data. Checked: GSAS-II reads the resulting instrument file and simulates.
9. **The goniometer radius is a lab setting**; it was fixed at 200 mm. The tungstate lab keeps 200 mm, GSAS-II's default.
10. **Switched-off effects work.** Any specimen effect can be omitted or set to `{"enabled": false}`. That previously failed validation, and a test now covers a lab with every effect off.
11. **Tungstate values carried over unchanged from V12.** The LAB.md settings reproduce the V12 generator protocol exactly: every specimen effect, the background, instrument ranges, counts and control sizes. Their provenance is in options 1–2 below.

### Scorer 6.1.0
12. **Scoring is identical to 6.0.0.** Only the source of the allowed-element list changed: the case record written at generation, or the old `elements` metadata for older cases.
13. **Unused legacy code removed.** That is the old profile-fitting evaluator, the old rubrics, a submission-check CLI and duplicated generator physics. The scorer is now 13 modules plus the replay worker and imports no generator code, so the old requirement that the generator match the scorer's copies is gone.
14. **Validated without model calls.** The 26 structural checks pass, and oracle and degraded projects on newly generated cases score as before (results below).

### Controller
15. **Batches are bound to LAB.md.** Batch freezing builds the protocol from LAB.md, and manifests carry `lab_sha256`. LAB.md is part of the infrastructure freeze, and protocol.json no longer exists.
16. **Other controller changes.**
    - `install.py --no-deploy` prepares a run locally without copying to EC2.
    - The process monitor's profile handling is now run-agnostic, and it reads up to 16,000 characters of LAB.md.
    - The v11 background-validation scripts are gone, superseded by `control/validation/`.
17. **Launch queue.** Across the Sol max eval15 launches, all 56 genuine failures were launch rejections: the service refused the first request within 2–3.5 s, before any solver output. No session failed mid-run. So the controller now admits one launch at a time, and sends the next only once the last has produced its first solver item (always an agent message, about 4 s in) or has been silent for 15 minutes. A rejected launch stays at the head of the queue and is retried every `capacity_retry_seconds` (60 s) by the existing recovery path, up to `max_concurrent_solvers` (10) running jobs. Run groups are scheduled breadth-first: every case and condition once, shuffled within the round, before any repeat. Previously the whole group was shuffled, up to ten jobs launched in one poll, and rejected jobs were retried newest-first at most one per minute even while launches were passing.
18. **Unchanged:** solver and researcher model gpt-5.6-sol at max effort, P0 bytes (sha256 `0c5def00…`, as in every eval15 baseline), and the vendored solver harness. (The guidance cap and revision cycle changed in decision 23.)

### After the first tungstate run (stopped 2026-10-22)
19. **Reference mismatch.** In the first run, 17 of b001's 18 phase truths were the COD entries the solver retrieves, changed only in Uiso. An untouched reference therefore scored 100% cell and site accuracy, and refinement could only lose credit. Packages v2–v4 learned exactly that: keep references untouched, coordinates fixed, and sample phases at their COD cells as internal angular standards. Real samples' phases never match their library entries exactly, so every phase's truth now differs from its registered model by LAB.md's `specimen.reference_mismatch`:
    - `perturb_model.perturb` in a new exact mode gives the drawn maximum principal cell strain and coordinate RMS themselves rather than upper bounds. The strain is symmetrized over the point group, coordinates move only within each site's freedom, and space group and composition are unchanged.
    - Draws are seeded by the recipe seed and phase ID, so twins share them, and specimen-control cases keep the mismatch: it describes the sample's phases, not specimen preparation.
    - A draw that the physical screen rates worse than its parent is redrawn from the next seed, up to 20 times. The screen uses the scorer's rules and `scorer/config.json` thresholds but is not imported, because the controller imports the generator and both have a module named `common`. On 75 registered models and six contact cases it agrees with the scorer's screen.
    - The solver's database keeps the registered parent. The case record keeps the parent's hash and path and the realized strain tensor and RMS.
    - The scorer is unchanged (6.1.0): it already reads the case's own references.
    - The curator's `perturb_model.py` variants remain available and receive the mismatch on top.
    - Tungstate values: cell strain log-uniform 0.02–0.3%, coordinate RMS log-uniform 0.004–0.02 Å, probability 1. These are generic priors for one oxide phase across ambient refinements, not derived from eval15 (option 11).
    - Code: `runtime/perturb_model.py`, `specimen.py`, `generate.py`, `labspec.py` and `generator_defaults.json`; TOOLS.md, `labs/TEMPLATE.md` and the tungstate LAB.md; tests; and three `parent_*` validation variants.

### After the second tungstate run (stopped 2026-10-23)
The second run (P0 and v1–v3 on one batch, five hours) learned the specimen terms but also learned to hold every coordinate, because with a coordinate mismatch of at most 0.02 Å the structural score made holding free and refining undetermined oxygen costly. Its packages grew more prescriptive with each revision, and v3's calibration-anchor rule reached Rwp 39% on one case. These decisions realign the objective and the process.

20. **Scorer 7.0.0: profile agreement is primary.** `score = 100 × (0.6 × 1/(1+D) + 0.4 × structural/100)`, zero on a hard physical failure. D is the mean Poisson deviance per bin of the verified `final.gpx` replay against the hidden noise-free pattern, so fitting noise cannot lower it and two models that produce the same pattern score the same. D = 1 (one noise standard deviation per point) earns half profile credit; the best fresh attempts of the second run had D 0.02–0.1. Without a verified, consistent project the profile term is zero, so the headline caps at 40. Rwp on the observed grid stays a separate diagnostic. The interplay is stated in the scorer, TOOLS.md and PROMPT.md: a solution is good when its predicted pattern matches the data to the noise floor, every structure is physically valid, and parameters the data cannot determine are left at their published values.
21. **Structural term credits only what the pattern can see.** Atom weights are Z × count (`scattering_population`) instead of √count, so oxygen in CaWO₄ carries 25% of site credit instead of 50% and in WO₃ 25% instead of 63%; a misplaced W costs more than a misplaced O (85.3 vs 93.7 on the single-phase fixture at 0.03 Å). The separate cell term is removed (`cell_cap` 0; cell error is still reported), because the profile term already measures it. Inventory, abundance and fraction credit are unchanged. Position scale 0.03 Å and the registration search are unchanged.
22. **Coordinate mismatch is larger and element-dependent.** `reference_mismatch` now takes `position_rms_A_by_element`; the generator applies each element's RMS exactly within its symmetry groups (caps: strain 0.5%, coordinates 0.08 Å). Tungstate values: cell strain 0.02–0.5%, metals 0.005–0.02 Å, oxygen 0.01–0.05 Å, probability 1. Dominant-phase oxygen refinement now lowers D, as it does on real data, while minor-phase oxygen stays undetermined and cheap to hold.
23. **Researcher process (PROMPT.md, TOOLS.md, settings).** A good package is defined as a few conditional procedures with trigger, execution check and rollback, demonstrated on fresh solvers; truth-scored diagnostics generate hypotheses and never validate a rule; controls count whichever way they go, and nothing freezes while controls are pending; promotion follows outcome (three attempts per case beating P0 on the mean without a case regressing beyond rollout variance), not per-case gates; at most two revisions per batch before the consolidated assessment and a new batch (`max_revisions_per_cycle` 2); guidance capped at 600 words (`max_guidance_words`); no absolute rules unless shown on two cases, and no numbers taken from LAB.md's generator ranges; keep solver slots busy with the next batch's baseline.
24. **Stops are final.** The second run's researcher filed recovery requests, ran `resume` and deleted `STOP.md` after the operator stop, treating the original task as re-authorization, then reverted. AGENTS.md now says a STOP.md or recorded user stop ends authorization until the user says to resume.
25. **Not implemented: product-phase solid-solution or occupancy mismatch** (option 14). It touches element consistency, composition withholding and the physical screen; it needs a scientific design first.

26. **Withholding by analogue, not only by composition.** `withhold_principal_composition` hid every entry with the product's exact composition and nothing else, so a withheld case's difficulty depended on which analogues happened to survive: b001-c04 hid ZnWO₄ while MgWO₄, NiWO₄ and CoWO₄ wolframites remained, a one-cation swap that P0 found unaided (v1 reached 90.5), whereas eval15's unsolved Sr₂WO₅ needs a two-site Ba₂ReO₅ prototype. Recipes now also accept `availability: "withhold_ids"` with an explicit COD ID list, and `runtime/library_neighbours.py` lists a model's same-stoichiometry library entries with an element-agnostic framework match (pymatgen's `StructureMatcher` with lattice scaling and a species-blind comparator; the scorer's own registration was tried first and rejected, because it is built for near-identical cells and rated the wolframite analogue CdWO₄ as unrelated to ZnWO₄), the cation/anion substitutions, and a tier 0–4. The researcher decides what to hide and records the nearest surviving tier; the generator refuses to hide an entry another phase of the case came from, and the EC2 mask refuses IDs absent from the index. Checked on ZnWO₄ against the whole library (425 ABO₄ oxides, 24 s): tier 0 its two polymorphs; tier 1 the Mg, Fe, Mn, Cu and Cd wolframites and ZnMoO₄; tier 2 seventeen mixed-cation wolframite-type oxides (NbInO₄, CoMoO₄, …); 397 unrelated. Tiers are a reporting convention, not a calibrated difficulty scale, and the cation-swap labels pair equal-multiplicity cations alphabetically. Solvers still index residual peaks routinely (82 of the Sol max eval15 attempts ran DICVOL; Opus indexed Pb₂WO₅'s residual to a C-centred cell and matched the Pb₂MoO₅ type), so tiers 2–3 are reachable; ab initio structure solution from powder data has not been attempted by any solver.

### After the third and parallel tungstate runs (stopped 2026-10-23)
Both runs ended with packages that fix failures (identity, inventory, import errors) but rarely complete the refinement: the solvers model zero offset or displacement but not both, keep fixed defaults for polarization and phase broadening, and leave the background order low. The parallel researcher spent about 70% of 11.25 hours waiting on 100 solver rollouts and about 1.3 hours on its own refinements. One generic, observable-only ladder (each step kept only if BIC improves) applied to the ten middling saved projects raised their mean headline from 69.0 to 78.1 without changing three near-floor controls, more than any package gained; on eval15, Opus's lead over Sol came from the same specimen modelling. The bottleneck is how quickly the researcher can test procedures, not whether good procedures exist.

27. **Process carried over from the parallel run.** PROMPT.md as reworked by the user (goal stated first; a solution is good when its predicted pattern matches the data to the noise floor and every structure is physically reasonable). Up to four development revisions per cycle and promotion when a package's three-attempt mean beats P0's beyond rollout variance on every case; these replace decision 23's two-revision cap and its promotion wording. The 600-word cap is unchanged.
28. **Procedure tests on saved projects.** `lab.py procedure-test --id ID --script PATH [--cases ... | --attempts ...]` runs a researcher script, called as a solver would call a package helper (`SCRIPT INPUT.gpx OUTPUT.gpx INPUTS_DIR`), on copies of every eligible saved `final.gpx`: completed, collected attempts with a verified replay, excluding cases whose prospective comparison is unfinished. Each copy runs in the evaluator's sandbox (bwrap, GSAS-II, no network, the scorer's restricted unpickler, only the work folder writable); the frozen scorer's own replay and D score the output, with independent Rwp, phase fractions and physical screens. The runner is its own systemd user unit (`control/procedure_runner.py`, `control/procedure_host.py`), so a long test never stalls dispatch and survives a controller restart; `lab.py wait ID` follows it and results land in `evidence/procedure-tests/ID/`. One test at a time; four workers, a 30-minute per-project limit (a request may double it) and at most 60 attempts (`procedure_test_*` settings). Results are truth-scored diagnostics like `score-investigation`: they rank and screen procedures; fresh rollouts still decide promotion. Saved attempts and their scores are never modified. Checked by 10 offline tests and an end-to-end run through `systemd-run` on four saved parallel-run attempts: an identity script reproduced every recorded D exactly; the ladder took D from 1.00 to 0.063, 0.66 to 0.173 and 0.58 to 0.082 and left the near-floor control unchanged, with every physical screen passing, at 17–141 s per project.
29. **Scorer 7.0.1: the parsimony sentence is removed.** "Parameters the data cannot determine are left at their published values" had been dropped from PROMPT.md but remained in TOOLS.md, `scorer/config.json` and the `score.py` docstring, all of which the researcher reads; the packages kept turning it into "keep source values" rules. The interplay text now matches PROMPT.md. Text only: eight parallel-run attempts rescored under 7.0.1 reproduce their 7.0.0 score, status, D, Rwp and structural term exactly; refrozen.
30. **PROMPT.md step 2 names the new test.** "Test it directly or through a solver continuation" became "Test it directly, across saved solver projects (`procedure-test`), or through a solver continuation." No other process clause was added, and no procedure was seeded into P0 or the packages.
31. **Operational fixes found by reviewing the parallel run and the controller.**
    - Solvers stop after four hours (`solver_timeout_seconds` 14400) and are scored on what they saved; a timed-out run previously became `interrupted`. A P0 baseline in the parallel run hung for 10.8 hours with no output while the researcher polled it; the longest of 257 finished attempts took 102 minutes.
    - `lab.py rescore` scores an attempt again after an `evaluator_error`, which otherwise left a prospective comparison open for good.
    - STATUS.md means include provisional (†) scores, as `scorer/config.json` already prescribes, with the mean without them beside it. In the parallel run all six flagged attempts were P0 failures (mean 30 against 71), so leaving them out flattered P0.
    - Both continuation arms use the requested package, so the instruction is the only difference; the generic arm used to keep the parent's package.
    - A failed evidence copy is retried for that job instead of stopping dispatch and status for every job.
    - GSAS-II's automatic `.bakN.gpx` copies, about 40% of an attempt, are deleted from the EC2 copy after collection; the collected evidence keeps them.
    - Procedure tests: TOOLS.md states the GSAS-II interpreter and how a shipped helper is called; without an explicit list the newest attempts up to the cap are used instead of an error; `lab.py cancel-test` stops a test.
    - `lab.py wait --seconds` accepts up to 1800 (was 60). About 45% of the parallel researcher's tool calls were 30-second polls, each a full model turn.

32. **Promotion by absolute target (the user's PROMPT.md rework, 2026-10-24).** A package is promoted when its initial validation runs reach noise-floor profile agreement with reasonable structures on every case (a clearly unlucky rollout may be waived), and then verified by completing three rollouts per case; otherwise investigation and revision continue. After four revisions without a promotable package, one consolidated package is assessed and promoted unless worse than the incumbent, so every cycle's package meets the next batch's P0 comparison. This replaces decision 27's "beats P0 on every case" rule, which no package could meet where P0 already sat at the floor (the parallel run's v2 met it on 0 of 6 b001 cases). Step 2 now asks for a one-page cross-case synthesis (each case's gap to the noise floor, what the best attempts did that the worst did not, interventions ranked by recoverable profile error) before interventions are designed; the parallel run's researcher had written the same per-case observations four times without aggregating them. Operator wording fixes: the investigation sentence asks for diagnosis, operation and a falsifiable prediction; carried-over cases stay in their original batch and run by separate requests, which is what the controller allows (it refuses to re-freeze an existing case).

## Options to review

1. **Provenance of the tungstate generator ranges.**
   - **Specimen and instrument ranges** were chosen in V12 to cover what solvers fitted on eval15: displacement about −520 µm, microstrain in the thousands of ppm, sizes around 0.15 µm. That is development data, not labels, but it is eval-informed.
   - **Grid, count levels and the metadata template** come from the eval15 input files.

   Alternatives: keep and disclose; widen to generic lab priors; or calibrate the instrument profile from a standard (Si or LaB₆) measured on the same instrument, which is the most defensible if each lab can supply one.
2. **Researcher visibility of the distributions.** Hiding the settings block from the researcher (prose only) would stop it designing cases around the generator's ranges, but is less transparent than V11.
3. **P0's sentence "The product composition and number of phases are unknown."** It holds for the tungstates. If the second lab's metadata gives a composition, choose between keeping P0 fixed across labs (comparable baselines) and a lab-specific baseline prompt.
4. **Reference library.** Both labs use the frozen filtered COD 2024. If hybrid perovskites are poorly covered there, the library becomes a lab setting.
5. **Geometry.** Only Bragg–Brentano reflection is implemented. Transmission or capillary (Debye–Scherrer) data would need GSAS-II's DisplaceX/DisplaceY and absorption terms instead of `Shift` and roughness.
6. **Specimen physics the generator lacks**, likely to matter for layered perovskites: anisotropic size and strain broadening, stacking faults, microabsorption, amorphous content.
7. **Texture axes.** The texture axis is drawn at random from LAB.md's list. For layered phases the stacking axis depends on the cell setting, so a per-phase rule (longest axis, or a curator-chosen axis) may be needed.
8. **Displacement parameters.** Registration resets every atom to Uiso 0.005 Å², and specimens draw one Uiso per phase. Organic cations need per-element or published displacement parameters.
9. **The physical screen's oxide-specific O–O review threshold** (1.8 Å) is harmless for halides but could become a lab setting, alongside H-contact rules for organics.
10. **The vendored solver harness** could be trimmed to the modules the runner uses (condition, run and their imports).
11. **Reference-mismatch magnitudes.** Now cell strain 0.02–0.5%, metals 0.005–0.02 Å and oxygen 0.01–0.05 Å RMS (decision 22), generic priors for solid-state oxide products across ambient refinements. The filtered COD keeps about one entry per phase, so an empirical prior from duplicate refinements would need a larger database.
12. **Specimen-control cases keep the mismatch.** The alternative, switching it off with the other specimen effects, would give literal-truth controls again.
13. **Profile and structural weights (60/40) and the D scale (half credit at D = 1)** are judgement calls, validated only on oracle, library-parent and refined projects. Changing them needs a scorer version bump.
14. **Product-phase solid-solution or occupancy mismatch** is not modelled. Real reaction products (for example Zn-rich wolframites) differ from database entries in composition as well as cell and coordinates; adding it requires deciding how element consistency, composition withholding and the physical screen treat partial occupancy.
15. **Truth-substitution attribution, held in reserve.** Substituting the true nuisance values into a saved project shows which modelling choices block the noise floor (with them, the solvers' own phase models reach D ≤ 0.025 in 8 of 10 middling parallel-run projects). It would point the researcher at the answer more directly than procedure tests do; add it only if procedure tests alone do not lead it to complete specimen refinement.
16. **Procedure tests on EC2.** They run on the 8-core controller host. If large tests become slow, run them on EC2 beside the solvers.
17. **EC2 storage.** Each attempt left about 180 MB on EC2 (18 GB for the parallel run); decision 31 removes the GSAS-II backups, about 40% of that. A larger volume would remove the need to archive between runs.
